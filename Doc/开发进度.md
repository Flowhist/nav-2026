## 当前实机联调状态

- Jetson 内核为 `5.15.185-tegra`，原配置未启用 `CONFIG_USB_SERIAL_CH341`。
- 已使用匹配 headers 和 `Module.symvers` 编译 `ch341.ko`，`vermagic` 为 `5.15.185-tegra SMP preempt mod_unload modversions aarch64`；当前仍从临时构建目录手动加载，尚未固化到启动流程。
- `brltty.service` 与 `brltty-udev.service` 已永久 mask；`embotic` 已加入 `dialout`，并安装项目声明的 `python3-serial` 运行依赖。
- 已安装 `/etc/udev/rules.d/99-finav-handle-usb-power.rules`，强制 VIA 父 Hub、Terminus 内部 Hub 和三个 CH340 保持 `power/control=on`。
- 修复前表现为首次打开可通信，串口关闭并空闲后第二次打开触发 USB 控制传输 `-110`；禁用父 Hub runtime autosuspend 后，首次读取 30 秒、关闭空闲 120 秒、第二次再读取 30 秒均成功，每轮 1495 帧、约 49.8 Hz，内核无新增 `-71`/`-110`。
- STM32 稳定路径为 `/dev/serial/by-path/platform-3610000.usb-usb-0:2.3.3:1.0-port0`；Modbus 从站 `1`、功能码 `0x03` 可稳定读取 `0x0003～0x0006`，其中档位 `0x0003` 会随 1～5 档正确变化。
- 实机 `0x0004`、`0x0005` 固定为 `5`、`4`，不提供有效摇杆轴数据；实际摇杆由 `SMC25usb32` 暴露为 `/dev/input/js0`，axis0/axis1、方向、满量程和松手回零均已验证正常。
- HID 摇杆不可按压，因此没有 HID button 事件属于正常现象。
- `0x0006` 空闲值为 `0x0003`，与文档的高电平触发定义不一致；屏幕两个触控按钮及导航键/摇杆键未产生可检测变化，经沟通确认为开发板侧问题，本阶段暂缓处理。
- `base_drive.sh` 实机联调已打通 HID 摇杆、STM32 档位、ROS 控制链路和底盘电机，当前可通过摇杆控制电机运转；轮子动态响应、速度连续域切换和控制指令连续性尚未完成验证。
- Windows 开发机已配置 Ed25519 密钥登录，可直接使用 `ssh embotic@10.86.81.100` 和 `scp`。

## 风险与约束

- 实机底盘测试必须保证物理急停可用，首次测试应架空驱动轮。
- 在完成至少 10 分钟连续通信和拔插恢复测试前，不固化临时内核模块，不升级 Jetson 内核。
- 三个 CH340 的 USB 序列信息重复，不应依赖会变化的 `/dev/ttyUSBN` 编号。
- 当前手柄到底盘已能驱动，但控制性能尚未验收；完成轮响应、速度连续域切换和指令连续性测试前，应继续采用架空车轮、低速和急停可用的受控测试条件。
- 屏幕触控按键的开发板侧问题暂缓，不应阻塞 HID 摇杆与 Modbus 档位链路开发。
- 屏幕常亮和界面刷新由 STM32/屏幕开发方负责，上位机只负责通信、指令转换和状态联动。
