# 开放路线巡行

## 实现范围

按当前要求，路线功能只扩展路径生成，复用原有路径跟踪控制器：

```text
当前位置 -> 原有规划器生成到入线点的路径
                     + 指定方向的剩余路线
                     -> 一条完整 /plan
                     -> 原有 nav_control
                     -> 原有底盘仲裁与电机控制
```

`route_tasks.py` 是任务管理器中的路线适配模块：读取已保存路线，复用编辑器平滑结果，计算附近线段投影点，并调用原有点规划器。候选无法到达时尝试其他投影点。规划成功后，将接入路径与路线剩余部分拼接，一次性交给控制器。

不增加入线后停车、独立对齐或另一套巡线控制状态机。正向/反向仅改变路线点列顺序，不要求倒车；开放路线到端点后由原有控制器停止。闭环不在本次范围内。

已删除上版新增的 `navigation_guard.py`、`route_tracking.py`、执行租约、预测制动检查、额外 1.26 米净空限制和独立弧长跟踪。地图、禁行区处理以及底盘接管/停车逻辑复用既有实现；本功能不新增动态障碍检测。

## 保留的接口

- 导航页：选择路线、开始、暂停、继续、取消。紫色虚线表示编辑路线，绿色实线表示完整执行路径。
- HTTP：`POST /api/nav/route`，字段 `action`、`map_name`、`route_id`。
- ROS：`/nav_task/command` 接收同一命令 JSON；`/nav_status` 沿用 `PLANNING/FOLLOWING/REACHED/FAILED/CANCELED`，增加人工 `PAUSED`。
- 摇杆接管沿用 `/nav_clear` 取消任务。人工继续重新规划当前位置到路线；保存路线后自动重新生成路径，已暂停的任务保持暂停。
- 之前要求的档位限速保留为输出缩放：档位比例为 `gear / 5`，路线限速通过 `/nav_task/speed_limit` 传给控制器。不改变原有 Pure Pursuit、转向、前瞻点和端点判定算法。
- 仍由现有导航服务启动这些节点，不新增 systemd 服务。

## 验证

`tests/test_route_execution.py` 验证附近投影、路径拼接、方向、不可达候选回退、旧结果隔离、暂停/取消、路线更新，以及原有控制器直接接收普通 `/plan` 并在最终端点结束。测试使用隔离 ROS 域，不驱动实车。
