# 在已有地图上继续建图

建图页选择具有 `.yaml/.pgm/.posegraph/.data` 的地图，点击“继续建图”。
只有栅格图或序列化数据缺失的地图不会出现在续建候选中。

1. 加载后处于定位模式，不向旧位姿图追加建图节点。
2. 点击“手动重定位”，在地图上拖动指定位置和朝向；也可点击“自动重定位”。
3. 用户目视核对机器人位置、朝向、雷达与墙体的对齐情况。
4. 直接点击“开始续建”，无需等待算法匹配状态或二次确认弹窗。
5. 扩展区域后保存地图，使用新的地图名，最后结束建图。

“匹配已更新”表示 STB 接受了定位扫描，不保证定位正确；全局重定位进程成功
退出也只表示候选位姿已发布，不会自动切换建图。匹配状态只供参考，是否对齐由
用户判断；地图未加载、节点状态过期、正在重定位或停止时仍禁止切换。
节点重启后始终重新进入定位阶段。

旧图上的画笔编辑只存在于 PGM，不会同步改变位姿图；续建生成栅格时不保证
保留画笔编辑。续建另存时会自动继承源地图保存过的地点、路线、禁行区和编辑设置，
包括地点朝向、路线速度等；旧版地点文件也支持导入。继承使用点击保存时的编辑信息，
保持地图世界坐标不变，不随栅格原点变化平移。地图文件与编辑信息均保存完成后才报告成功。
源地图不变；若目标地图已有编辑文档或旧版地点文件，则保留其现有内容。
安全净空只有标记为 `editor_override` 时使用地图保存值，其余情况跟随当前规划配置；
修改 `path_plan.yaml` 后需重新启动导航，地图编辑器也按当前配置显示默认净空。
回环优化可能改变局部地图形状，使用前请核对地点、路线和禁行区是否仍与新图对齐。

## 实现位置

- `src/rosnode/continued_mapping_node.cpp`：继承 Humble STB 混合节点，启动即定位，
  匹配状态提示、用户触发模式切换、周期状态和序列化保存。
  栅格保存直接使用 Nav2 map_io，从位姿图生成栅格后写入 PGM/YAML，避免
  上游存图服务启动额外地图订阅进程时超时；新建图和纯定位节点不受影响。
- `launch/sub/slam_toolbox.launch.py`：仅 `mapping` 且 `map_file` 非空时使用新节点。
- `server/continued_mapping.py`：地图校验、会话与状态检查、续建 HTTP 操作。
- `server/ros_bridge.py`：读取 `/slam_toolbox/continued_mapping_state`。
- `server/process_manager.py`：复用 STB `set_localization_mode`，重定位退出不再自动续建。
- `server/tests/test_continued_mapping.py`：离线 HTTP 与服务管理回归。
- `tests/test_continued_mapping.py`：隔离 ROS 加载、匹配、切换、保存及重新加载测试。

接口：`POST /api/runtime/mapping/start` 接受 `{ "map_file": "旧图名" }`；
空对象保持新建图行为。定位使用 `POST /api/mapping/initialpose`
（`x/y/yaw_deg`）或 `POST /api/mapping/relocate`；开始续建使用
`POST /api/mapping/resume`（空对象即可）。存图和停止复用现有接口。

首次部署需构建 `finav` 并重启 Web 以加载新接口。启动建图服务时会加载新节点。
隔离测试必须指定空闲 ROS 域和 `ROS_LOCALHOST_ONLY=1`，并设置
`FINAV_CONTINUED_MAPPING_EXECUTABLE` 与 `FINAV_TEST_POSEGRAPH`（不含扩展名）。
离线/模拟扫描测试不能代替现场定位与扩图验收。
