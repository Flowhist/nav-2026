# 转向半径修改方案（暂不实现）

## 背景

当前手动控制和导航控制在近似原地旋转时通常下发 `linear.x = 0`、`angular.z != 0`。差速换算后左右驱动轮速度近似完全对称反向，车辆试图绕中心原地旋转。

实车前部两个从动轮是万向轮。当万向轮朝向为前后方向、没有顺着旋转方向横过来时，原地旋转起步需要先强行调整万向轮朝向。受车重和电机驱动上限影响，车辆起步转向困难。

## 目标

把近似原地旋转改成小半径前进圆弧旋转，让车辆先产生滚动趋势，帮助前万向轮自然摆正，降低起步阻力。

## 作用范围

计划放在 `scripts/control/base_control.py` 的 `_apply_twist()` 中统一处理所有进入底盘驱动的 `/cmd_vel`：

- 键盘控制：生效
- 摇杆控制：生效
- Web 控制：生效
- 导航控制：生效

这样不用分别修改 `joy_control.py`、`base_control_router.py`、`nav_control.py`，所有近似原地转向行为保持一致。

## 触发条件

仅处理近似原地旋转：

```text
abs(linear.x) < turn_arc_linear_deadband
abs(angular.z) > turn_arc_angular_deadband
```

完全停车保持不变：

```text
linear.x = 0
angular.z = 0
```

已有明显线速度的普通转弯保持不变。

## 处理方式

触发后给 `linear.x` 注入正向线速度，`angular.z` 保持原方向和大小：

```text
linear.x = max(
    turn_arc_linear_min,
    abs(angular.z) * wheel_separation * turn_arc_wheel_ratio
)
```

差速模型：

```text
v_left  = linear - angular * wheel_separation / 2
v_right = linear + angular * wheel_separation / 2
```

`turn_arc_wheel_ratio` 建议设为 `0.60`。它略大于 `0.5`，可让内侧驱动轮也倾向同向滚动，而不是反向硬扭，更利于万向轮摆正。

## 建议参数

```yaml
turn_arc_enabled: true
turn_arc_linear_min: 0.06
turn_arc_linear_deadband: 0.02
turn_arc_angular_deadband: 0.02
turn_arc_wheel_ratio: 0.60
```

## 里程计与定位影响

当前 `/odom_encoder` 不是按下发的 `/cmd_vel` 积分，而是按 `whill.get_velocity([left_motor_id, right_motor_id])` 读到的真实左右驱动轮速度积分：

```text
v_forward = (v_left + v_right) / 2
omega = (v_right - v_left) / wheel_separation
```

因此，只要真实驱动轮速度产生前向平均分量，`/odom_encoder` 会体现前向运动。EKF 使用 `/odom_encoder` 的 `vx` 和 `vyaw` 输出 `/odom`，SLAM Toolbox 再结合 `/scan + /odom + TF` 做定位修正。

需要注意：如果驱动轮打滑或车体受阻，轮式里程计仍会反映驱动轮转动而不一定等于真实车体运动，SLAM 只能部分修正。

## 风险与后续

- 导航末端原地对准会变成小弧线对准，可能带来少量位置变化。
- 近障碍物场景需要后续在导航算法中处理安全边界。
- 当前先不实现该方案，仅作为后续修改依据。
