# 独立常驻避障实现方案

> 2026-10-28 需求更新：人工与自动模式均允许依据当前控制意图修正前进方向，绕开局部障碍，无安全通路则停车。此要求替代下文旧阶段“人工模式只允许限速或停车”的约束。现已增加默认关闭的仲裁接入；算法仍留在 Finav，后续整体迁入 base_control。当前实现与限制以 [避障接口](../reference/避障接口.md) 为准；下文保留原设计阶段记录。

## 1. 目标与边界

- 实现独立后台常驻避障服务，随底盘使用周期运行，不随建图、导航、Web 或跟随任务退出。
- 仅开发避障；不引入 YOLO、人员识别、人员轨迹或跟随逻辑。
- 使用 MRPT `mrpt-nav` 的 PTG 核心能力，C++ 实现；不启动整套 Nav2，不依赖全局地图或 SLAM。
- 常驻碰撞保护始终计算；主动绕障仅在自动模式有有效目标时计算，无目标保持保护和待机。
- 所有实际运动仍经 `base_control`。避障服务不直接发布 `/cmd_vel`、不操作电机。
- 下文描述最终目标；当前 Finav 观测版的实现、运行方式和验证边界见第 9 节。底盘保护接入及迁移仍未实施。

### 开发约束（2026-10-22）

- 当前阶段所有新增实现放在 `finav` 仓库，功能成熟并完成阶段验收后再移植到 `base_control`；不提前修改底盘仓库或线上控制链。
- 代码保持简洁、直观、计算量有界。配置和静态几何在启动时解析，数据进入模块时统一校验，处理循环不重复解析配置或执行同一项检查。
- 减少重复审查和与本次改动无关的测试；保留失联停车、数据过期、运动覆盖和急停等直接影响控制正确性的检查。验证以受影响功能及真实故障场景为准。
- 优先复用现有驱动、URDF、服务启动工具和可独立使用的算法。仅在确有两个使用方时提取共享逻辑，不复制整个底盘仲裁器或建立通用框架。
- 修改涉及的旧逻辑确认无调用方、无部署入口后直接清理；保留仍被现有节点或 demo 使用的实现，不把既有未提交改动当作废弃代码。
- 与导航同时运行是验收场景。平稳运行须以当前 Jetson 的并发负载、处理延迟和资源实测为依据，不能只凭限频或离线测试宣称保证各种情况。

## 2. 模块与控制链

先作为现有 `finav` 包内的独立模块开发，不新增独立 ROS 包，不塞入
`person_follow` demo，也不加入默认导航 launch。文件按现有结构放置，按需创建：

| 路径（相对 finav） | 职责 |
| --- | --- |
| `src/rosnode/obstacle_avoidance_node.cpp` | ROS 输入输出和调度 |
| `src/avoidance/`、`include/finav/avoidance/` | 不依赖运行中 ROS 节点的 C++ 算法及必要头文件 |
| `config/obstacle_avoidance.yaml` | 参数、资源上限和过期时间 |
| `launch/sub/obstacle_avoidance.launch.py` | 独立启动入口 |
| `scripts/service/` | 按需扩展现有服务工具 |
| 隔离验证（历史 `tests/`） | 模拟输入、故障和性能测试；脚本已于 2026-10-30 按用户要求清理，结果见开发与验证文档 |

开发阶段只输出 `/avoidance/*` 下的状态与建议，不发布到现有速度输入话题。
可以观察导航输入，但导航速度本身不能替代 MRPT 所需的局部目标。
此阶段尚未为实际底盘提供碰撞保护。下图是成熟后迁移接入的目标链路：

```text
Gemini SDK 深度 + 内参 ─→ 障碍提取、地面过滤、降采样 ─┐
/odom_encoder ─────────→ 自运动补偿、短时局部记忆 ───┼→ 常驻避障核心
KS114 独立驱动 ────────→ 近障门控、逐路有效性检查 ──┘

自动模式目标 → MRPT 局部规划 → base_control 自动输入
手柄 / Web / 其他自动输入 → base_control 仲裁
                                     ↓
                              带序号的候选速度
                                     ↓
                              常驻碰撞保护审核
                                     ↓
                        base_control 校验结果及看门狗
                                     ↓
                         /cmd_vel → 现有底盘驱动
```

- 保留手柄接管、急停、故障锁定、自动输入冲突的现有优先级。
- 人工模式只允许限速或停车，不擅自改变驾驶方向；自动模式允许 MRPT 主动绕行。
- MRPT 输入为局部目标、障碍点、实际位姿/速度、车体轮廓和运动限制；禁止将任意手柄速度伪造成远处目标。
- 无可行运动、计算异常或超时返回停车，不返回上一轮运动指令。

## 3. 输入与固定参数

坐标统一为 `base_link`：后驱动轮轴心中点的地面投影，+x 前、+y 左、+z 上；长度单位米。

| 项目 | 来源 / 参数 |
| --- | --- |
| 车体轮廓 | `finav/urdf/whillcar.urdf` 的 collision 几何，变换到 base_link 后取平面外包络；当前主车体 x=[-0.25,0.84]、y=[-0.375,0.375]（2026-10-22 用户修正宽度为 0.75 m），不是以原点居中的矩形 |
| 安全余量 | 单独配置，不修改 URDF 外廓；初始建议 0.05 m，待现场验证 |
| 前置相机 | Orbbec Gemini 305，位置 (0.575,0.2775,0.727)，yaw=-30°、pitch=0°；沿用现有倒置图像纠正约定，避免重复旋转 |
| 位姿和实际速度 | `base_control` 发布的 `/odom_encoder`；核对时间戳与坐标系，不使用目标速度冒充实际速度 |
| 超声接口 | 复用 DCCS dauxi 驱动，`interfaces/msg/KS114State`；串口只允许一个驱动持有 |
| 雷达 | 初版不强制依赖；预留 LaserScan 输入用于后续覆盖扩展，不改变现有 `/scan` 合约 |

超声位置来自之前测量，朝向按用户最新确认的严格前、后、左、右方向：

| 位置 | 地址 | x | y | yaw |
| --- | --- | --- | --- | --- |
| 前左 | 0x10 | 0.64 | 0.31 | 0° |
| 前右 | 0x11 | 0.64 | -0.31 | 0° |
| 左侧 | 0x12 | 0.57 | 0.32 | +90° |
| 右侧 | 0x13 | 0.57 | -0.32 | -90° |
| 后左 | 0x14（用户确认） | -0.10 | 0.1675 | 180° |
| 后右 | 0x15（用户确认） | -0.10 | -0.1675 | 180° |

前四路地址已实测；后两路地址与位置由用户于 2026-10-30 确认，六路静止通信已验证，记录见开发与验证文档。2026-10-22 用户补充：前左、前右、左侧、右侧探头中心离地 0.28 m，后左、后右离地 0.10 m。安装位已同步到 `urdf/whillcar.urdf`；当前方向检查及独立门限以避障接口文档为准。

## 4. 避障处理规则

1. 相机只提供深度和内参，不跑目标检测；独立适配层拥有相机，后续其他功能共享数据，不能重复打开同一设备。
2. 将有效深度转换到车体坐标，剔除地面和自体回波，按 collision 高度范围及余量提取障碍；先降采样再交给 MRPT。
3. 在连续里程计坐标系保留短时障碍记录；区分占用、已观测空闲、未知。过期障碍移除后对应区域回到未知，不能自动当作空闲。
4. MRPT 负责生成候选动作；独立审核运动扫掠区域、制动距离及观测覆盖。空点云、无回波或视野外不等于安全，禁止仅凭 MRPT 接收到的点集放行未知区域。
5. 初版保留四路超声原始距离 <=0.5 m 停车门控；缺失、无效或任一路采样过期同样停车。检查 reading.stamp，不用汇总消息时间续期。
6. 0.5 m 为探头到障碍距离，不是车体净空。固定侧向门限可能阻止通过窄门；第一阶段接受保守停车，不为过门自动缩小阈值。
7. 超声声束不是精确障碍点；5.657 m 的含义尚未验证，不视为覆盖整片区域的空闲证据。倒车、原地转向需验证相应扫掠区域覆盖，否则拒绝动作。
8. 沿用底盘速度上限，配置实际加减速度及制动参数。初次运动验证限速 0.15 m/s、0.3 rad/s，不把这组调试上限当作最终车辆能力。

## 5. 接口与失效保护

新接口统一使用 `/avoidance/*`，先放在 Finav 内；优先使用字段语义合适的现有消息，
需要自定义接口时放在 `finav/msg/`，避免用无时间戳速度消息或 JSON 字符串承载控制协议。
以下仲裁请求与结果协议先通过模拟输入验证，迁移时才接入实际底盘：

| 接口 | 内容 |
| --- | --- |
| `request` | 仲裁后的候选速度、来源、模式、会话 ID、递增序号、有效期限 |
| `result` | 对应会话及序号、允许速度、STOP/LIMIT/PASS 状态、原因 |
| `goal` | 自动模式局部目标，含坐标系、时间戳、有效期限和取消机制；独立测试使用，不接入跟随 |
| `status` | 传感器年龄、覆盖状态、最近障碍、处理耗时、保护状态及停车原因 |

- 仲裁器保持 `/cmd_vel` 唯一发布者；避免候选速度与审核结果形成话题回环。
- 候选请求采用最新帧队列；记录发送时刻和待确认请求。允许使用仍有效且同一来源/模式的已审核结果，不能因每次发新请求就永久丢弃异步结果。
- 来源切换、急停、取消、速度意图改变或进程重启时，使旧结果立即失效；结果重复、乱序、过期不续期。
- 建议初始审核有效期 100 ms、传感器过期上限 500 ms，均需结合实际制动距离和更新率验证；审核过期由 base_control 主动输出零速。
- 原驱动 `cmd_timeout=0.35 s` 作为第二层失联停车，不能代替审核看门狗。保护启用后，避障进程崩溃不得自动旁路恢复运动。
- 同步 RPC 或 MRPT 求解不得阻塞底盘仲裁、手柄接管及急停回调。

## 6. 常驻部署与预算

- 单独 systemd 用户服务，由底盘使用周期的 target 拉起；不绑定 finav 建图/导航/Web 服务，不在模块导入时打开硬件。
- 上述自动拉起属于成熟后的部署目标。Finav 开发阶段使用独立启动入口，默认不安装自启动、不修改现有 target；按需复用现有服务脚本，不复制另一套服务管理器。
- 启动顺序：传感器可用、保护就绪后才允许非零输出；重启期间保持停止，恢复后只接受新的有效请求。
- 默认无 GUI、不发布全分辨率调试图像、不逐帧刷日志；状态限频、日志轮转、队列和局部记忆均有上限。
- 初始频率预算：深度障碍更新 10～15 Hz，MRPT 主动规划 10 Hz，碰撞审核 20～50 Hz；依据实测调整，不通过延长过期门限掩盖过载。
- 记录每模块 CPU、RSS、P50/P95/P99 与最大耗时；发布频率不能冒充新数据频率。建议保护审核 P99 <20 ms、规划 P99 <100 ms，均为待验证目标。
- MRPT 固定版本，只链接必要核心库；不要直接依赖已弃用的 `mrpt_reactivenav2d` ROS 封装。
- 传感器输入只保留最新数据，过载时丢弃旧帧，不能积压处理。MRPT 计算与输入接收分离，最多一个求解任务；相同数据不重复规划，无有效目标不求解。
- 热路径避免反复申请大块内存；深度先按固定步长或栅格降采样，限制障碍点数和局部记忆容量。线程数显式设定并按并发测试调整，避免数学库自动占满 CPU。
- 相机和超声设备保持单一持有者。导航已运行时复用现有里程计及可用传感器话题，不额外拉起底盘、雷达、EKF 或导航；与相机 demo 共用设备时须通过同一采集层，不能各自打开设备。

## 7. 实施顺序与验收

1. 在 Finav 内实现算法核心、URDF 轮廓加载、配置和模拟输入；完成 MRPT 最小 API 验证及版本锁定。算法与 ROS 适配分开，便于后续移植。
2. 实现深度障碍提取、里程计补偿、超声门控；只输出状态和建议，不接底盘运动。
3. 在 Finav 测试程序中模拟候选请求和异步结果，用隔离 ROS 域验证来源切换、迟到结果、崩溃、恢复和超时语义；此时不改 base_control，不宣称已具备真实急停或停车保护。
4. 用独立局部目标测试 MRPT；不修改跟随、建图、导航或 Web 业务逻辑。
5. 离线测试直门、斜入门、门后转弯、狭窄不可通行、转弯外侧擦碰、动态障碍、深度空洞、盲区、超声失效、里程计跳变、输入断流。
6. 完成 Finav 阶段验收：离线功能与故障场景通过，实机传感器观测正常；分别测试避障单独运行、与导航并行、导航启动/停止及传感器断流。记录 CPU、RSS、处理延迟、数据年龄和导航链路频率，检查长时间运行的内存与日志增长。这是移植前的功能及资源验收，不是实际底盘保护验收。
7. 功能成熟且阶段验收完成后，再移植到 base_control 并接入异步审核与超时停车；复用原仲裁器优先级和故障逻辑。接入后先用隔离环境验证急停、接管和看门狗，再在现场明确确认后做低速运动测试，记录制动距离、最小净空和误停车。
8. 最终验收常驻运行：导航/Web 全部停止时保护仍工作；空闲不持续规划；服务被杀或卡住时车辆按期限停车。无法通过时稳定停车，不以绕行成功掩盖碰撞或超时。

当前阶段交付：Finav 内的算法与节点、参数文件、独立 launch、离线及故障测试、并发性能报告、启动/停止命令。
成熟后交付：迁移后的底盘保护接入、常驻服务及回退命令、实机运动验收记录。禁止未经实测宣称安全过门。
