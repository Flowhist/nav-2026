# Finav 服务部署

## 服务边界

使用机器人运行用户的 systemd user manager，不以 root 运行 Web 或 ROS 节点。

底层实现和服务入口已归独立仓库 `base_control`，底层服务统一命名为 `base_control.service`，详见 [底盘仓库拆分](底盘仓库拆分.md)。

| 单元 | 内容 | 开机启动 | 异常重启 |
| --- | --- | --- | --- |
| `base_control.service` | 电机驱动、HID/STM32 手柄、速度仲裁器 | 随 target 启动 | 不自动重启 |
| `finav-web.service` | HTTP、页面、ROS 状态桥接 | 随 target 启动 | 自动重启 |
| `finav-mapping.service` | 现有 `map.launch.py` | 否 | 不自动重启 |
| `finav-navigation.service` | 现有 `nav.launch.py` | 否 | 不自动重启 |
| `finav.target` | 统一组织上述服务，启动底层和 Web | 可启用 | 不恢复导航任务 |

建图与导航互斥，共用的雷达、IMU、EKF、TF 随各自 launch 启停，当前阶段不再细拆。
建图/导航依赖底层服务，底层退出时一起停止；Web 保持运行以显示故障。
Web 退出或重启不停止底层、建图、导航，仅结束 Web 自己启动的一次性重定位辅助进程。
底层任一必要进程退出会结束同组进程，服务标记失败，避免仅剩部分控制链路。
服务的 active 状态表示进程在运行，设备在线和定位就绪仍以 ROS/Web 状态为准。

## 安装

先确认当前用户具备现有 CAN、串口和 HID 权限，ROS Humble 和工作区已构建。
所有服务使用同一个 ROS 环境；自定义 ROS_DOMAIN_ID 等设置应对全部 Finav 单元保持一致。

```bash
cd /home/embotic/nav_workspace
source /opt/ros/humble/setup.bash
colcon build --base-paths src/base_control src/finav --packages-select base_control finav --symlink-install
source install/local_setup.bash
python3 src/finav/scripts/service/install_services.py
```

安装命令只写入当前用户的服务配置并执行 daemon-reload，不启动硬件，也不启用开机启动。
不要使用 sudo 运行安装脚本。生成的文件为：

- `~/.config/systemd/user/finav*.service` 和 `finav.target`：服务单元。
- `~/.config/finav/services.json`：当前仓库路径和运行数据目录。
- `~/.local/state/finav/`：参数、日志、ROS 日志；遵循 XDG_CONFIG_HOME/XDG_STATE_HOME 覆盖。

只生成供检查的文件：

```bash
python3 scripts/service/install_services.py --output-dir /tmp/finav-units
systemd-analyze --user verify /tmp/finav-units/finav*.service /tmp/finav-units/finav.target
```

导航/Web 使用导航仓库配置，底层使用 `base_control.paths.config_dir()` 定位的配置；底层支持 `BASE_CONTROL_CONFIG_DIR` 覆盖。服务通过工作区安装的 ROS 包运行，仓库或工作区移动后需要重新部署。

## 迁移和开机启动

先通过旧终端正常退出 `start_finav.sh` / `base_drive.sh` 及独立运行的 Web、建图、导航。
新服务检测到旧进程时会拒绝启动，不会按进程名杀死它们。
安装后旧入口脚本会拒绝再次启动，以免出现两个控制者；尚未安装服务的开发环境继续使用原有模式。

确认机器人周围安全、摇杆回中、可以进行实车测试后执行：

```bash
sudo loginctl enable-linger embotic
systemctl --user enable finav.target
systemctl --user start finav.target
```

linger 使用户服务管理器无需登录即可随开机启动。仅启用 `finav.target`，不要单独启用建图/导航。
底层没有网络依赖，Web 的故障不会停止摇杆链路。默认网页地址为 `http://<Jetson-IP>:8010`。
开机启动底层意味着电机控制链路可用；现有急停、零速复位和指令超时保护继续保留。

## 日常操作

网页原有建图、导航启动/停止按钮保持不变；导航必须先选择地图。
网页保存配置后的“底盘控制重启”会重启整个底层服务，同时停止正在运行的建图/导航。
网页“重启 Finav”只恢复底层和 Web，不自动恢复旧导航任务。

```bash
systemctl --user status base_control.service finav-web.service
systemctl --user restart finav-web.service
systemctl --user stop finav-navigation.service
systemctl --user stop finav.target
systemctl --user start finav.target
```

Web 和服务共享运行参数。导航所选地图保存在 `~/.local/state/finav/navigation.json`；
重启 Web 后会查询 systemd 并重新读取参数，不依赖旧 Web 进程的 PID 缓存。
Web 监听设置可写入同目录的 `web.json`，例如 `{"host":"0.0.0.0","port":8010}`，随后重启 Web。
底盘/手柄参数继续编辑仓库的 `config/base_control.yaml` 和 `config/handle.yaml`。

各服务输出在运行数据目录的 `base.log`、`web.log`、`mapping.log`、`navigation.log`。
Web 原有日志查看/清空入口继续使用；底盘、手柄、仲裁器显示同一份底层日志。
底层服务按输出来源逐行添加固定前缀，标准输出、错误输出及异常堆栈均包含来源：

```text
[base_control] ...
[handle_control] ...
[base_control_router] ...
```

服务启动器自身的错误可用 `journalctl --user -u base_control.service -n 100` 查看。
日志文件为追加写入，长期无人值守部署应配置主机日志轮转。

## 验证与回退

```bash
python3 -m pytest -q tests/test_service_packaging.py
FINAV_TEST_SYSTEMD=1 python3 -m pytest -q tests/test_service_systemd_integration.py
```

第二项只创建带随机名字的临时 sleep 服务，验证互斥、Web 重启隔离、底层停止传播及不恢复导航；不会启动任何 ROS 或硬件节点，退出后清理临时单元。

回退前先安全停止机器人，执行 `systemctl --user disable --now finav.target`，确认四个服务均已停止。
然后移除本次生成的四个 service、target 和 `services.json`，执行 `systemctl --user daemon-reload`。
保留运行数据和地图后，即可重新使用旧脚本；不要同时使用两套启动方式。
