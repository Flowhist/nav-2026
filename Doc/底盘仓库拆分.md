# 底盘仓库拆分

2026-09-17：底盘与手柄已迁移到同级独立 Git 仓库、ROS 包 `base_control`。这是代码所有权拆分，控制话题、仲裁优先级和电机控制算法保持原实现。

```text
nav_workspace/src/
  base_control/
    base_control/  # 驱动、手柄、仲裁、共享协议和服务实现
    nodes/      # ros2 run 的薄入口
    config/     # base_control.yaml、handle.yaml
    launch/     # base.launch.py、handle.launch.py
    scripts/    # 独立服务安装与启动
    checks/     # 无硬件验证
  finav/
    scripts/control/  # 导航任务、规划和路径跟踪
    scripts/imu/      # IMU
    launch/ config/   # 建图、定位、导航及传感器集成
    server/ sim/      # Web 和导航仿真
```

## 依赖方向

`finav` 依赖 `base_control`，反向没有依赖。Web 从 `base_control.handle_hid`、`base_control.handle_protocol` 导入既有映射函数；配置读写通过 `base_control.paths.config_dir()` 定位底层配置。页面上的 `base_control.yaml`、`handle.yaml` 名称保持不变，文件实际归新仓库维护。

雷达、IMU、EKF、SLAM 和含传感器安装位姿的整机 URDF 留在导航集成项目；底盘独立发布 `/odom_encoder`，不重复发布 odom TF。新增同事的功能应通过 `/nav_cmd_vel` 或经仲裁器接入的其他来源提交指令，避免直接发布 `/cmd_vel` 绕过仲裁。

## 构建与运行

在工作空间根目录执行：

```bash
source /opt/ros/humble/setup.bash
colcon build --base-paths src/base_control src/finav --packages-select base_control finav --symlink-install
source install/local_setup.bash
python3 src/finav/scripts/service/install_services.py
```

服务名称为 `base_control.service`、`finav-web.service`、`finav-mapping.service`、`finav-navigation.service` 和 `finav.target`。底层单元的实际启动入口归 `base_control`，可以脱离导航仓库单独安装，详见新仓库 README。安装器仅写配置，不启动硬件。

原 `base_drive.sh` 留作兼容入口，转到新包的交互启动脚本，保留终端键盘输入。原 `start_finav.sh` 调用新包中的节点；已安装服务的机器继续使用 systemd。直接运行 Web 前需要 source 工作空间，因为共享手柄模块现在是正式安装的 Python 包。

CAN 使用外部 `omnilibs` SDK，新仓库未复制 SDK。其位置通过 `base_control.yaml` 的 `omnilibs_path` 参数配置；当前 Jetson 配置和设备路径已迁移。SDK 工作目录也可通过 `driver_working_dir` 配置，不再硬编码指向导航仓库。
