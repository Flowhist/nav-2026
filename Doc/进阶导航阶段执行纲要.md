# 进阶导航阶段执行纲要

本文定义 Finav 在现有定点导航基础上增加“固定路线巡航”和“禁行区规划约束”的阶段性实施方案。目标是渐进扩展现有自研规划与控制链路，不引入完整 Nav2，也不改变底盘最终控制接口。

## 1. 总体目标

新增两类能力：

1. 固定路线巡航：先规划短路径接入已注册路线，再按路线规定方向巡线；开放路线到端点结束。2026-09-09 确认不实现闭环、计圈和持续运行。
2. 禁行区约束：Web 注册的旋转矩形禁行区在运行时进入全局规划和路线校验，定位使用的 SLAM 原始地图保持不变。

保持现有外部主链路：

```text
/goal_pose 或 /nav_task/command
  -> 导航任务管理
  -> 全局规划/固定路线
  -> /plan
  -> nav_control.py
  -> /nav_cmd_vel
  -> base_control_router.py
  -> /cmd_vel
```

## 2. 已确定的设计原则

- 路线是“有方向的有序点列”，不是无方向折线。
- 第一版每条路线只保存一个确定方向，不做双向自动选择；需要反向时使用编辑器中的行进方向选择或另建路线。
- `forward` 表示按 `waypoints` 数组顺序行驶，`reverse` 表示逆序行驶；切换方向不修改 waypoint 几何顺序。
- 闭环的顺/逆时针由 waypoint 顺序推导；Web 必须显示方向箭头和顺逆时针结果。
- 入线点取平滑路线线段上的投影点，不局限于已注册 waypoint。
- 入线点不能只按欧氏距离选择，必须同时检查方向和 A* 可达性。
- 禁行区只叠加到规划障碍栅格，不写回 SLAM 原地图。
- 路线预览、入线规划和定点规划必须共用同一套占用阈值、未知区域和安全膨胀规则。
- `/plan` 保持为下游唯一参考路径接口，避免多个节点无仲裁地同时发布。
- 第一版使用轻量 ROS 话题和状态反馈；确有跨系统任务编排需求时再升级为自定义 Action。

## 3. 最小数据模型升级

将地图编辑文档升级为 `schema_version: 2`，旧文档加载时补默认值：

```yaml
routes:
  - id: route-001
    name: 走廊巡航
    closed: false
    direction: forward       # forward | reverse
    repeat_count: 1          # 0 表示持续巡航，仅闭环允许
    speed_limit_mps: 0.35
    waypoints:
      - {id: wp-1, x: 0.0, y: 0.0}
      - {id: wp-2, x: 2.0, y: 0.0}
```

Web 编辑器同步增加：

- 路线方向箭头、首尾标记和闭环接缝显示。
- 正向/反向行进方向选择。
- 支持选定路线线段，并在该线段中点增加关键点。
- 闭环顺时针/逆时针提示。
- 巡航次数和路线限速。
- 与地图障碍、禁行区冲突的明确提示。

暂不增加分段动作、停靠、分支路网和每段独立属性。

## 4. 运行时模块边界

### 4.1 共享规划约束

抽取共享约束逻辑，复用现有禁行区栅格化代码：

```text
/map + <map>.editor.yaml
  -> 原始障碍 + 禁行区
  -> 统一安全膨胀
  -> planning_grid
```

`planning_grid` 供定点规划、路线平滑校验和入线候选检查共同使用。可选发布 `/planning_map` 作为 RViz/Web 调试视图，但 SLAM Toolbox 仍使用 `/map`。

### 4.2 导航任务管理

新增 `nav_task_manager.py`，统一管理定点导航与路线巡航，并作为 `/plan` 的权威发布者。规划器改用内部话题输入输出，外部 `/goal_pose` 和 `/plan` 契约保持不变。

建议状态：

```text
IDLE -> PLANNING -> FOLLOWING -> REACHED
IDLE -> SELECTING_ENTRY -> JOINING -> ALIGNING -> PATROLLING -> COMPLETED
任一阶段 -> FAILED / CANCELED
```

发布 `/nav_status`，至少包含任务类型、阶段、路线 ID、当前线段、进度、圈数和失败原因。

### 4.3 路线跟踪

- 开放路线：从入线投影点截取指定方向的剩余路线，跟踪到端点后停车。
- 闭环路线：使用累计弧长进度，前瞻点按路线总长取模，跨越末点后回到首段。
- 控制器维护单调路线进度和局部线段搜索窗口，防止自交路线跳到错误分支。
- 到达入线点后先按路线切向对齐，再进入巡线。

### P3：开放路线巡航

2026-09-09 范围修订：按用户要求收敛为点到路线的路径生成，将接入段与剩余路线拼接后交给原有控制器。已撤回新增安全层、重复净空校验和另一套跟踪状态机。下列条目保留为原始方案，当前实现以 [开放路线巡行](开放路线巡行.md) 为准。

- 加载并校验指定路线及其 revision。
- 将机器人投影到各路线段，按“距离、朝向、A* 可达性”选择入线候选。
- 使用现有 A* 规划当前位置到入线点的短路径。
- 到达后对齐路线切向，发布指定方向的剩余路线并巡线至端点。
- 支持路线限速、取消、定位/TF 超时停车和禁行冲突拒绝。

验收：从路线两侧和不同朝向均能选择合理、可达的入线点；不会隔墙吸附；开放路线严格按注册方向运行并在端点停车。

### P4：闭环路线与持续巡航

2026-09-09：用户明确取消本阶段。下列条目仅保留为原始规划记录；现有闭环编辑数据保留，但执行接口拒绝闭环路线。

- 控制器增加闭环模式、弧长取模和圈数统计。
- 支持单圈、指定圈数和持续巡航。
- 处理闭环接缝、路线自交和重新接入。
- 禁行区或路线 revision 变化时暂停并重新校验，禁止继续使用失效路线。

验收：跨接缝速度连续且不误判到达终点；圈数准确；持续巡航可被 `/nav_clear`、摇杆接管和底盘故障可靠停止。

### P5：与 Finav Pro 局部避障衔接

- 固定路线继续作为全局参考路径，不承担动态障碍绕行。
- MPPI/局部规划器负责短时绕行、等待和回归路线。
- Safety Guard 对最终控制统一执行静态禁行区、实时障碍和数据超时检查。

验收标准并入 `Doc/finav-pro-solution.md` 的 MPPI 与 Safety Guard 阶段，不在巡线第一版重复实现动态避障。

## 7. 当前明确不做

- 不迁移到完整 Nav2、Lanelet2 或 Open-RMF。
- 不在第一版实现通用路网、路线分叉、会车调度和多机器人交通管理。
- 不把动态障碍永久写入地图或禁行区文件。
- 不用复制多圈路径的方式模拟闭环巡航。
- 不绕过 `base_control_router.py` 直接向底盘发布导航速度。
