# 独立避障接口

状态：行驶审核采用双 2D 雷达融合观测和六路超声，复用局部栅格、MRPT 与制动扫掠。相机保留观测和人员跟随，不参与行驶否决，也不是避障启动前提。Web 仍通过系统菜单的统一开关启停审核，默认关闭。实现不代表实车验收完成。2D 雷达只覆盖扫描平面，不能保证识别平面上方、下方或透明、低反射障碍。设计历史见 [独立避障方案](../plans/独立避障.md)，验证边界见 [开发与验证](../开发与验证.md)。

## 当前接口

| 话题 | 类型与约定 |
| --- | --- |
| `/scan` | 现有融合 `sensor_msgs/LaserScan`，继续供建图、导航及 Web 使用；无穷值不作为避障空闲证据 |
| `/avoidance/scan` | `finav/FusedScan`，同一融合节点输出两路有限回波点云及各自雷达起点，坐标均为 `base_link`，两路保留各自采集时间 |
| `/avoidance/depth`、`/avoidance/camera_info` | 相机仍可发布；行驶审核节点不订阅 |
| `/odom_encoder` | 复用底盘里程计，`odom -> base_link`；分别按两路雷达采样时间匹配前后里程计，端点各不超过 100 ms，再插值位姿 |
| `/ultrasonic/device/state` | 复用 `interfaces/KS114State`，逐路检查总线、地址、时间戳、失败次数和距离 |
| `/avoidance/request` | `finav/AvoidanceRequest`，`base_link` 下候选速度、session、递增 sequence、source、采集时间和有效期，最长 100 ms |
| `/avoidance/result` | `finav/AvoidanceResult`，保留请求身份、时间及有效期，不通过重复检查续期；可保持、限速、修正前进方向或停车，只有仲裁器校验后才输出到底盘 |
| `/avoidance/goal` | `geometry_msgs/PointStamped`，`odom` 下距离当前车体不超过 3 m 的局部目标，需在 0.5 秒内刷新 |
| `/avoidance/cancel` | `std_msgs/Empty`，清除目标；早于取消时间的目标不恢复规划 |
| `/avoidance/suggestion` | `geometry_msgs/TwistStamped`，规划及覆盖检查后的建议；非零建议保留计算时间，超过 150 ms 不复用。仅供观察，不能直接接到底盘 |
| `/avoidance/status` | `diagnostic_msgs/DiagnosticArray`，最多 5 Hz，条目名 `avoidance_observation`；诊断字段见下文 |
| `/avoidance/obstacles` | `sensor_msgs/PointCloud`，`base_link` 下的二维障碍投影，z=0；最多 5 Hz、4096 点，仅有订阅者时发布，过期占用格不发布 |

没有仲裁器请求时，局部目标仍可独立测试。独立节点不订阅 `/plan`，不发布 `/cmd_vel`。开启避障时，仲裁后的摇杆、键盘、Web、导航或跟随速度通过同一请求接口接受修正；独立 `/avoidance/goal` 的建议不进入底盘。

同步缓存最多保存 32 条里程计和 8 组融合观测，优先采用最新的已匹配组。位置线性插值，航向按最短角差插值，不外推。每路点云分别按对应采集位姿转入 odom 栅格；沿实际雷达起点至有限回波的射线更新空闲，终点覆盖为空间占用。无回波、无效值、遮挡后方和没有射线覆盖的区域保持未知，不把 `/scan` 的无穷值当作空闲。

两路采集时间差不得超过 100 ms，任一路必须有有限回波，源时间及接收时间均受 0.5 秒有效期约束。融合节点拒绝旧帧重发、未来帧、异常扫描元数据；任一路停止时不再产生可用双路观测，审核在有效期内转为零速。缓存和地图不能延长传感器有效期。重复里程计或扫描时间戳不续期；里程计回退、坐标系或位姿异常清理历史并拒绝当轮输出。当前运动审核使用最新有效里程计。整帧分别匹配位姿，尚未执行单束扫描运动去畸变。

## 控制意图与开启方式

`base_control_router` 启动参数 `avoidance_enabled` 默认 false。启动后通过 `/base_control_router/set_avoidance`（`std_srvs/SetBool`）切换；须先松开手动控制或取消导航，使原始意图归零。移动中切换会返回失败。运行时以服务响应为准，启动参数不表示实时开关状态。

```bash
ros2 service call /base_control_router/set_avoidance std_srvs/srv/SetBool '{data: true}'
ros2 service call /base_control_router/set_avoidance std_srvs/srv/SetBool '{data: false}'
```

Web 开启时先启动观测服务，再调用上述底盘接口；关闭时先确认底盘退出避障，再停止观测服务。直接调用 ROS 底盘接口不会管理 systemd 服务，日常启停使用 Web 统一开关。缺少接口时开启失败；缺少避障进程、有效传感器或有效审核结果时，开启状态下保持零速，不自动退回原始指令。

- 前进意图先按同比例限速保留曲率，默认上限 0.15 m/s、0.3 rad/s。路径空闲时保留该指令；默认提前检查 1 m 的运动弧长，障碍或覆盖限制触发 MRPT 搜索，最多检查 5 个候选方向。目标位于前视区域以外，并随当前指令重新生成，不保存为独立自主任务。
- 所有绕行候选接受同一车体扫掠与实际速度制动检查。预览内转角超过 90 度的绕行候选不采用。人工前进预查命中已知障碍、绕行失败后，对已限速的原始指令依次尝试 0.75、0.5、0.25 倍线速度和角速度，保留曲率，只检查 `lookahead=0` 的反应/制动扫掠范围；首次通过即输出 `slowed_for_obstacle`，全部失败则停车。不设最低爬行速度，不通过倒车、原地旋转或提高速度脱困；自主来源和原始倒车、原地转向策略不变。
- 减速分支及绕行都要求有效空闲覆盖。实际速度制动检查不通过时直接停车；减速输出仍接受超声方向、传感器新鲜度、50 ms 计算截止时间、请求过期/替换与底盘校验。无跨请求限速缓存；离散档位不保证速度平滑，当前制动预测参数仍需实车标定。
- 请求来源 `joystick`、`web`、`keyboard` 属于人工控制，但切换雷达后不再豁免未知网格。人工、自主、倒车、转弯及减速候选均检查有效覆盖，稀疏扫描或盲区不能当作通路。
- 仲裁器检查 session、sequence、source、原始时间戳、100 ms 有效期、速度边界与当前意图。松杆、来源切换、急停、故障或结果过期不能沿用旧修正。小幅输入变化最多容忍线速 0.02 m/s、角速 0.03 rad/s；不能跨反向或回中沿用结果，也不能超过当前前进速度。
- 超声数据校验对所有来源保持一致，任一已配置探头缺失、无效或过期仍停车。自主控制在任一路距离 <= 该路门限时停车。人工控制将门限内近距回波按 URDF 安装位置和测距轴线投影为局部点，在反应及制动时间范围内检查整个矩形车体与点的间距变化；实际运动或最终输出接近任一回波即停车。车体外正间距回波允许不靠近的平行运动；回波在包络内或边界上时仍要求最终间距增大才放行。转弯检查包含侧面与车尾，缺少安装信息时不做方向豁免。声束和物体形状尚未标定，轴线点模型不是完整障碍轮廓；后方没有完整防碰撞覆盖。

超声门限在 `config/obstacle_avoidance.yaml` 配置，单位米，支持任意有限正数，无 0.5 m 下限。`ultrasonic_stop` 是统一默认值；`ultrasonic_stop_distances` 可指定四项或六项独立值，依次对应地址 0x10 起的探头。前四路为前左、前右、左侧、右侧；六项模式额外检查 0x14、0x15，必须先确认后左/后右实际对应关系，并在 `ultrasonic.yaml` 启用采集。省略数组或设为 `[]` 时仍检查前四路并使用统一值。零、负数、NaN、无穷值或其他数组长度均拒绝启动。

当前实机配置为 `[0.40, 0.40, 0.25, 0.25, 0.35, 0.35]`，即前两路 0.40 m、左右侧 0.25 m、后两路 0.35 m。2026-10-30 用户确认后左为 0x14、后右为 0x15，六路采集均已配置。六路模式下任何后路缺失、无效或过期同样停车；缺少该路安装位时不作方向豁免。参数在节点启动时读取，修改后需重新启动感知服务；状态中的 `us_16_stop_m` 起显示各路实际采用值，六路模式同时发布 `us_20_*`、`us_21_*`。此配置仅用于独立避障审核，不修改人员跟随自身的超声门控。

算法、传感器适配、消息和配置目前在 Finav；底盘仅有可选接口适配和独立的请求校验器 `base_control/avoidance_gate.py`。关闭避障时底盘不导入 Finav。后续迁移可整体移动核心、ROS 节点、消息、配置和测试，并替换仲裁器 `_setup_avoidance()` 的消息导入位置；无需移动导航、Web 或全局地图逻辑。

## 观测诊断字段

### 绕行失败诊断

`/avoidance/status` 增加 `planning_*` 字段，只解释控制意图审核，不改变 `/avoidance/result.reason` 或输出速度，也不混入独立 goal 的规划记录。字段每轮重新初始化；传感器失效或请求校验失败时不会沿用上轮轨迹。

| 字段 | 含义 |
| --- | --- |
| `planning_evaluated` | 本轮是否调用了控制意图核心；false 表示被前置门控挡住或无请求 |
| `planning_original_stage` | 原始指令检查位置：input、actual_motion、direct_check、preview，或 not_checked |
| `planning_original_reason` | 原始指令结果，如 obstacle、unobserved_sweep、pass；preview 的拒绝原因是触发搜索的原因 |
| `planning_search_status` | not_run、goal_reached_or_invalid、goal_unmappable、planner_no_motion、planner_invalid_output、attempts_exhausted、accepted |
| `planning_attempts` | 实际调用 MRPT 搜索次数，0–5；包含未产生运动候选的尝试 |
| `planning_candidate_N_stage/reason` | 第 N 次尝试，N 从 0 开始。stage 为 planner、direction、safety_check 或 preview；reason 为具体失败原因或 pass |
| `planning_candidate_N_linear/angular` | 经过限速的候选速度；planner 阶段未产生速度时为 0 |
| `planning_candidate_N_planner_speed/planner_direction` | MRPT 原始速度量及方向；不是底盘速度，非有限值不序列化 |
| `planning_slowdown_attempts` | 原方向低速制动检查次数，0–3 |
| `planning_slowdown_scale` | 通过的比例 0.75、0.5 或 0.25，相对于已限速原始指令；未通过或未尝试为 0 |
| `planning_slowdown_N_reason` | 第 N 次低速检查结果，N=0/1/2 对应 0.75/0.5/0.25；pass 或具体拒绝原因 |

例：`planning_original_reason=obstacle`、`planning_search_status=planner_no_motion` 表示原始预查发现障碍，搜索返回非正速度；若 candidate 的 stage=safety_check、reason=unobserved_sweep，则表示生成了候选，但制动范围内覆盖不足；stage=preview 表示制动范围通过后，较长预查仍被拒绝。

诊断沿用低频采样，不保证捕获每个瞬态请求。按 request_session/sequence/source 关联，最终是否放行仍看 `request` 与结果速度：accepted 的绕行候选或通过的低速候选随后仍可能被超声、请求过期或计算超时否决。减速不覆盖原始预查与绕行失败记录；每轮清空所有轨迹及比例。设计约定见 [预查与制动分离](../plans/避障预查与制动分离.md)。

`schema=2`，`drives_chassis=false` 表示本节点不直接发布底盘速度，不代表仲裁器未启用修正。`message` 是当前输入门控原因，`request` 与 `goal` 分别是请求审核及独立目标规划原因。诊断快照不能作为运动控制或瞬态故障的完整记录。

`request_reviews/corrections` 是有效请求进入算法的次数及算法给出修正的次数（发布前仍可能因计算超时等被改为停车），`plans/plans_hz` 仅统计独立 `/avoidance/goal`，不能用后者判断控制意图修正是否运行。

- `frames/plans/obstacles`：累计处理帧、累计规划次数、缓存障碍点；`frames_hz/plans_hz` 是相邻诊断间的处理频率。
- `observation_source=dual_lidar`、`lidar_left_age_s/right_age_s/receive_age_s`：输入来源、两路采样年龄与接收年龄；`lidar_left_points/right_points/publishers` 表示有限点数与融合观测发布者数。
- `lidar_odom_matched`、`lidar_odom_before_s/after_s`：本轮是否匹配两路采集位姿及端点间隔上界；`lidar_pose_x/y/yaw` 为左路采集位姿。`lidar_expired`、`lidar_invalid`、`lidar_odom_unsynchronized` 分别表示过期、无效及无法匹配。相机年龄不再是行驶审核字段。
- `us_16_*` 到 `us_21_*`：六路超声的 `distance_m/age_s/online/valid/failures/matches`，对应地址 0x10–0x15；旧四路配置仅发布到 `us_19_*`。
- `request_source/session/sequence/age_s/ttl_s`、`goal_present/frame/x/y/age_s`：当前请求与缓存目标；`request/result/suggestion/actual` 各自的 `_linear/_angular` 单位为 m/s、rad/s。无请求、无目标时相关字段缺省。
- `tick_ms/tick_mean_ms/tick_max_ms`：本次、诊断周期内平均及最大算法计算耗时，不含结果发布及诊断序列化；`deadline_misses` 是累计计算超过 50 ms 的次数。
- `cpu_percent`：避障进程相邻诊断间的 CPU（100% 为一个核，首帧缺省）；`rss_mib` 是当前进程 RSS；`uptime_s` 是节点运行时长。均不包含相机及其他进程。
- 启动时实际采用的算法参数同配置键名，外廓 `footprint_0..4` 为 xmin/xmax/ymin/ymax/height。雷达外参由融合节点从 URDF 静态 TF 获取；参数不是标定已完成的证明。

功能测试可直接读取 ROS 诊断。Web “感知”页消费雷达障碍投影和六路超声；兼容字段 `depth_live` 目前表示雷达图层有效性，`observation_source` 明确来源。超声弧带宽度是视觉示意，不代表已标定声束角或已测得物体边界。
