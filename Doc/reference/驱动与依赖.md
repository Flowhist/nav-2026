环境基线为 Ubuntu 22.04、ROS 2 Humble、Python 3。软件依赖以两个仓库的 `package.xml`、`CMakeLists.txt` 为准；机器路径与设备地址需按目标机器调整。

## 底盘与手柄

`base_control/config/base_control.yaml` 的 `omnilibs_path` 当前指向 `/home/embotic/DCCS/src/site-packages`。SDK 不在两个 GitHub 仓库中，重装时须单独获取；保留完整依赖，不能只复制 `omnilibs/`。历史部署使用 python-can、canopen、loguru、pymodbus、NumPy、SciPy。

当前配置为 `PCAN_USBBUS1`、500000 bit/s，左右电机 ID 为 1、2。PCAN 内核模块需匹配 Jetson 内核，并提供 PCAN-Basic 动态库。2026-08-13 的已用安装包为 `peak-linux-driver-8.18.0.tar.gz`，本机来源目录 `/home/embotic/DCCS-ENVinstaller/package/driver/`；这些是历史部署记录，不是新机器的自动安装保证。

手柄使用稳定的 `/dev/serial/by-path/`、`/dev/input/by-id/` 路径，配置位于 `base_control/config/handle.yaml`。速度显示写十进制寄存器 31，单位为 0.01 km/h，寄存器 2 只读；实际轴输入来自 USB HID。

| 左 / 右雷达 | `10.86.81.111:8080` / `10.86.81.112:8080`，TCP |

| 避障观测 | 同一融合节点发布 `/avoidance/scan` (`finav/FusedScan`)，保留两路有限回波、起点及各自时间戳；无回波不等于空闲 |

| IMU 串口与标定 | `config/imu.yaml` |
| 传感器安装位姿 | `urdf/whillcar.urdf` |

Jetson 与雷达应在同一网段。雷达直连网口不设置默认网关，避免影响远程连接。先检查两路原始扫描，再检查融合数据；静止正常、运动时变形，应排查时间戳、TF 和里程计。

雷达厂商代码来源及修改见 [README.vendor.md](../../third_party/hinson_he_lidar/README.vendor.md)。厂商许可证仍需确认；DM-IMU 原始包版本与校验记录待补。需检查 `libboost-thread-dev` 是否安装，不应假定 rosdep 能完整恢复外部 SDK、内核驱动和厂商环境。

## Gemini 安装记录

2026-10-16 暂用测量值统一保存在 `urdf/whillcar.urdf` 的四个
`front_camera_*` 数值属性中；人员跟随模块启动时直接读取，不需要运行 TF 或 xacro。
修改这些属性后重启人员跟随模块生效。

| 参数 | 暂用值 |
| --- | --- |
| x：向车前 | 0.575 m |
| y：向车左 | 0.2775 m |
| z：距地面 | 0.727 m |
| yaw：相对车头，左转为正 | -30 度（偏右） |

`base_link` 是后驱动轮轴心中点的地面投影；不是轴心高度平面。
暂把测量点当作彩色相机光心，俯仰为零；机壳到光心偏移、镜头畸变未进一步标定。
URDF 中 `front_camera_link` 采用前/左/上轴，
`front_camera_upright_optical_frame` 采用右/下/前轴，对应纠正倒置后的图像，
不能直接用于未翻转的 SDK 原始图像。

SDK 深度按光轴 Z 使用，结合内参还原目标三维位置，再按相机 yaw 旋转并加安装平移。
表格 XYZ 是车体坐标，`DIST=hypot(x,y)`，`BEARING=atan2(y,x)` 以度显示。
高度用于目标 z 估计，不计入平面跟随距离。

2026-10-22 补充记录：前四路探头中心离地 0.28 m，后两路 0.10 m，安装位置已写入 `urdf/whillcar.urdf`。准确声束角与覆盖仍未标定；跟随门控不把这些坐标转换为障碍物点。
独立 `ultrasonic.yaml` 轮询六路，避障检查全部六路，人员跟随仍只使用前四路。沿用 DCCS 驱动和设备路径，
探头间隔 10 ms，汇总发布周期 50 ms；轮询周期配置仍为 100 ms，但六路串行读取实际耗时决定每路更新频率。不修改 DCCS 原有六路配置，串口超时仍为 100 ms，避障样本有效期仍为 0.5 秒。
先确认串口未被其他进程占用，再单独启动现有驱动（不启动 DCCS 全栈）：

```bash
source /opt/ros/humble/setup.bash
source /home/embotic/DCCS/install/local_setup.bash
ros2 run dauxi dauxi --ros-args -r __ns:=/ultrasonic \
  -p config_file:=/home/embotic/nav_workspace/src/finav/config/ultrasonic.yaml -p enable:=1
```

另一个终端仅监听测距，不连接底盘、不发布速度：

```bash
source /opt/ros/humble/setup.bash
source /home/embotic/DCCS/install/local_setup.bash
python3 /home/embotic/nav_workspace/src/finav/scripts/control/ultrasonic_gate.py --seconds 120
```

终端显示位置名称、地址、距离、样本年龄，以及同一停车门控的 STOP/READY 状态；
READY 仅表示超声门控通过，不代表人员跟随已准备好。工具不发布任何速度。
可用 `--stop-distance` 调整验证阈值（默认 0.5 m），控制程序对应配置为 `person_follow.yaml` 的 `ultrasonic_stop`。
在四个位置分别放置/移走障碍物，应出现 STOP/READY；停止驱动后应出现过期 STOP。
2026-10-16 前左障碍物测试中，0x10 连续五次为 0.065 m，20 次四路读取均通过 CRC。
此结果只验证测距，未验证实际底盘制动。0x11 无近障时常为 5.657 m，
其无回波/量程含义尚未查明；程序未将该数值定义为故障码，不能据此证明前方安全。
数值不变但时间戳持续更新也不能证明探头正常。

## 新机器核对顺序

1. 准备 ROS Humble 及 manifest 依赖，确认 Python 科学计算、串口和 YAML 模块可用。
2. 安装匹配内核的 PCAN 与 SDK，给机器人用户配置串口、HID、CAN 权限。
3. 按机器调整设备路径、雷达网口和 SDK 路径，再构建两个仓库。
4. 按 [服务部署](../部署与运维.md) 安装服务，逐项验证底盘、手柄、雷达、IMU、定位；不要用编译成功代替设备联调。
