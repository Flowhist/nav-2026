# 部署与运维

新机器先按 [驱动与依赖](reference/驱动与依赖.md) 准备外部 SDK、设备权限和 ROS 依赖。本文集中维护安装与服务管理命令；页面操作见 [操作指南](操作指南.md)。

## 构建与安装

在工作区根目录执行构建和服务安装；`src/` 下需要同时有 `finav` 和 `base_control` 两个仓库：

当前默认构建包括避障观测模块，需要 MRPT 2.4.2 和 DCCS `interfaces`，详见 [驱动与依赖](reference/驱动与依赖.md)。下面的 DCCS 路径是本机路径，新机器应替换为实际安装位置。只构建原有导航组件时，跳过 DCCS 的 source 命令，并在 colcon 命令末尾添加 `--cmake-args -DFINAV_BUILD_AVOIDANCE=OFF`。

```bash
cd /home/embotic/nav_workspace
source /opt/ros/humble/setup.bash
# 默认避障构建使用现有 KS114 消息包。
source /home/embotic/DCCS/install/local_setup.bash
colcon build --base-paths src/base_control src/finav --packages-select base_control finav --symlink-install
source install/local_setup.bash
python3 -m pip install -r src/finav/requirements/web.txt
python3 src/finav/scripts/service/install_services.py
```

上述构建已限定包路径，避免工作区存在同名包时冲突。安装脚本只生成当前用户的 systemd 单元，不启动服务、不启用自启动；不要用 sudo 执行安装脚本。仓库位置改变后需重新构建、安装。

## 服务启动与管理

所有 `systemctl --user` 命令均由安装服务的机器人用户执行，不加 sudo。启动底盘前确认现场安全、手柄回中。

服务职责与退出行为见下文“服务边界”。

安装脚本同时生成按需启动的 `finav-perception.service` 和共享 `finav-lidar.service`。网页系统菜单的避障开关启动感知及雷达依赖；感知包括六路超声、避障审核和用于观测/跟随的相机。相机进程退出后独立重试，不连带停止雷达避障。感知关闭时释放相机和超声，雷达共享服务保持运行供建图和导航使用；`systemctl --user stop finav-lidar.service` 可显式释放雷达，停止 `finav.target` 时一起停止。

双雷达驱动、融合及机器人静态 TF 由 `finav-lidar.service` 唯一管理。建图、导航和感知单元均依赖它；systemd 设置 `FINAV_SHARED_LIDAR=true`，建图/导航 launch 因此跳过自身的雷达与模型启动。直接命令行启动建图/导航且共享服务已运行时，也必须设置该环境变量，避免重复占用 TCP 8080。共享服务未运行时，直接 launch 保留原来的独立雷达启动行为。自定义雷达 IP 应统一修改 `config/lidar.yaml`，共享服务不会使用建图/导航单独传入的 IP。

这些传感器服务不单独设为开机启动；相机沿用 `.venv-vision` 环境，超声默认加载 `/home/embotic/DCCS/install/local_setup.bash`，异机可在服务环境中设置 `FINAV_DCCS_SETUP`。更改服务关系后重新运行安装脚本并 daemon-reload，安装脚本本身不启动硬件。

### 日常启动与停止

```bash
# 启动底盘和网页
systemctl --user start finav.target

# 也可以分别启动
systemctl --user start base-control.service
systemctl --user start finav-web.service

# 只重启网页，不影响手柄控制
systemctl --user restart finav-web.service

# 停止全部服务，包括已启动的建图和导航
systemctl --user stop finav.target
```

浏览器访问 `http://<机器人IP>:8010`，机器人本机可访问 `http://localhost:8010`。在网页中启动、停止建图或导航；导航前先选择地图，建图与导航不能同时运行。

开发调试阶段默认关闭口令登录，浏览器可直接访问。可选访问控制设置见 [Web 访问](#web-访问)。

单独停止服务：

```bash
systemctl --user stop finav-mapping.service
systemctl --user stop finav-navigation.service
systemctl --user stop finav-web.service
systemctl --user stop base-control.service
```

停止或重启底盘会同时停止建图、导航；单独停止或重启 Web 不会停止这些服务。整套重启用 `systemctl --user restart finav.target`，只恢复底盘和 Web，不恢复之前的导航任务。

### 状态和日志

```bash
systemctl --user status base-control.service finav-web.service finav-mapping.service finav-navigation.service --no-pager

# 节点输出：底盘日志同时包含手柄和仲裁器
tail -n 50 -F ~/.local/state/finav/base.log
tail -n 50 -F ~/.local/state/finav/web.log
tail -n 50 -F ~/.local/state/finav/mapping.log
tail -n 50 -F ~/.local/state/finav/navigation.log

# 服务启动器错误
journalctl --user -u base-control.service -u finav-web.service -n 100 --no-pager
```

日志窗口按 `Ctrl+C` 只退出查看，不会停止服务。`active` 仅表示服务进程在运行，设备连接和定位是否就绪仍需查看日志或网页状态。

### 开机自启动

```bash
# 无需登录即可运行用户服务；在机器人用户的终端执行
sudo loginctl enable-linger "$USER"
systemctl --user enable finav.target

# 检查是否已启用
systemctl --user is-enabled finav.target

# 取消下次开机自启动，不停止当前服务
systemctl --user disable finav.target
```

开机仅启动底盘和 Web，建图、导航仍由网页按需启动。`enable` 不会立即启动服务；需要立即启动时另执行 `systemctl --user start finav.target`。

底盘配置位于 `base_control/config/`，导航配置位于 `finav/config/`；保存后按网页提示重启对应服务。已安装服务的机器不要再运行旧 `start_finav.sh` 或另起同一套 ROS 节点。

## 服务边界

| 单元 | 内容 | 启动与退出行为 |
| --- | --- | --- |
| `base-control.service` | 电机、手柄、速度仲裁 | 随 target 启动；服务失败不自动重启 |
| `finav-web.service` | HTTP 与 ROS 桥接 | 随 target 启动；异常退出自动重启 |
| `finav-lidar.service` | 双雷达、融合、机器人静态 TF | 感知/建图/导航共享，按依赖启动 |
| `finav-mapping.service` | 建图、IMU、EKF | 网页启动；与导航互斥，依赖共享雷达 |
| `finav-navigation.service` | 定位、规划、跟踪及传感器 | 网页选地图后启动；与建图互斥 |
| `finav.target` | 统一管理上述服务 | 启动只拉起底盘和 Web，不恢复导航任务 |

底盘退出会停止建图、导航。Web 重启不停止其他服务，但会结束其一次性重定位辅助进程。`active` 仅表示进程存活，设备在线及定位就绪需查看 ROS/Web 状态。

## 安装与配置位置

安装脚本使用机器人用户运行，不加 sudo；需先正常退出旧脚本启动的节点。它只生成单元并刷新 systemd，不启动硬件或开启自启动。已安装服务的机器不要混用旧启动脚本。

| 位置 | 内容 |
| --- | --- |
| `~/.config/systemd/user/` | `base-control.service`、三个 `finav-*.service`、`finav.target` |
| `~/.config/finav/services.json` | 服务所属仓库及运行目录 |
| `~/.local/state/finav/` | 日志、运行参数、ROS 日志 |
| `base_control/config/` | 底盘与手柄参数；`BASE_CONTROL_CONFIG_DIR` 可覆盖 |
| `finav/config/` | 传感器、定位、建图和导航参数 |

配置/状态目录支持 `XDG_CONFIG_HOME`、`XDG_STATE_HOME`。Web 监听参数可写入状态目录的 `web.json`，例如 `{"host":"0.0.0.0","port":8010}`，随后重启 Web。`navigation.json` 保存网页所选地图。各服务的 `ROS_DOMAIN_ID` 应保持一致。

仓库移动后需重新构建、安装。只渲染单元而不部署，可在工作区执行：

```bash
source /opt/ros/humble/setup.bash
source install/local_setup.bash
python3 src/finav/scripts/service/install_services.py --output-dir /tmp/finav-units
systemd-analyze --user verify /tmp/finav-units/*.service /tmp/finav-units/finav.target
```

## Web 访问

开发调试阶段默认关闭口令登录，页面和 API 可直接访问；不会读取或生成口令文件，已有口令文件也不会自动启用登录。

只有在 Web 服务环境中显式设置 `FINAV_WEB_AUTH=1` 才启用浏览器原生 Basic 身份验证，用户名为 `finav`。启用后口令优先取 `FINAV_WEB_PASSWORD`；未配置时首次启动自动生成到 `${XDG_STATE_HOME:-~/.local/state}/finav/web-access.key`，文件权限为 0600，不写入日志。由部署用户在机器人本机查看该文件并输入浏览器。

更换口令可在停止 Web 后更新该文件，或修改服务环境中的 `FINAV_WEB_PASSWORD`，随后只重启 `finav-web.service`。不要把口令写入仓库。HTTP 本身不加密，跨不可信网络时通过 HTTPS 反向代理或安全隧道访问；代理需保留原始 Host。

写请求需要 `Content-Type: application/json`，禁止跨站来源。默认最多 32 个 HTTP 连接、8 个实时画面流，连接读写超时 10 秒，请求体上限 4 MiB。Web 停止时关闭桥接线程并终止自己启动的存图任务；建图、导航主体服务仍独立管理。

## 故障排查

| 现象 | 先检查 |
| --- | --- |
| 网页打不开 | `systemctl --user status finav-web.service`、`web.log`、IP 和 8010 端口 |
| 服务 active 但底盘不动 | `base.log` 中设备连接、故障和仲裁状态 |
| 电机报 `33555 / STO` | 现场急停旋钮及 STO 回路；已遇到过未释放物理急停导致启动失败 |
| 手柄不在线 | `handle.yaml` 与 `/dev/input/by-id/`、`/dev/serial/by-path/` 的路径是否匹配 |
| 雷达连接失败 | `config/lidar.yaml`、雷达网络连通性、TCP 8080 是否被其他进程占用 |
| RViz 无点云 | `/scan` 数据、Best Effort QoS、Fixed Frame 与 TF |
| 导航不动 | `/nav_status`、`/plan`、`map -> base_link` TF，目标是否位于障碍/未知区或禁行区 |

节点输出默认在 `~/.local/state/finav/{base,web,mapping,navigation}.log`；服务启动器错误查看 `journalctl --user -u <服务名> -n 100`。底盘日志保留 `[base_control]`、`[handle_control]`、`[base_control_router]` 前缀。日志追加写入，长期运行需配置轮转。

## 视觉推理环境

正式视觉环境为 `/home/embotic/nav_workspace/.venv-vision`，启动入口自动选择，无需 activate。控制节点仍使用系统 ROS Python。`FINAV_VISION_ENV` 可指定其他路径；模型默认缓存 `~/.cache/finav/vision`，可用 `FINAV_VISION_MODELS` 指定。直接依赖维护在 `requirements/vision.txt`，传递依赖固定在 `requirements/vision-constraints.txt`，安装快照在环境内 `requirements-resolved.txt`。

安装脚本针对本机 Python 3.10、JetPack 6 / TensorRT 10.3，从 NVIDIA apt 源提取与系统运行库匹配的 Python 绑定到虚拟环境。新机器须先安装匹配的 CUDA/TensorRT 运行库。

```bash
cd /home/embotic/nav_workspace/src/finav
bash scripts/vision/setup.sh
bash scripts/service/run_vision.sh prepare
cd /home/embotic/nav_workspace
source /opt/ros/humble/setup.bash
source /home/embotic/DCCS/install/local_setup.bash
colcon build --base-paths src/finav --packages-select finav --symlink-install
source install/local_setup.bash
```

模型首次下载与 TensorRT 优化需要时间。更新模型时先停止跟随，删除缓存中对应 `.onnx`、`.engine` 后重新 prepare；引擎与运行库不兼容时也须重新生成。模型来源与许可证见 [人员跟随接口](reference/人员跟随.md#上游来源)。

未加入开机自动行驶服务；启动步骤见 [人员跟随](操作指南.md#人员跟随)。共享相机已有发布者时跟随使用 `start_camera:=false`。历史临时相机服务若仍引用已删除旧路径，应停止并改用 `vision_camera.launch.py`。

## 卸载服务部署

先安全停车，执行 `systemctl --user disable --now finav.target`，确认四个服务均已停止；如果曾单独启用底盘服务，也需禁用它。再移除本部署生成的五个单元及 `services.json`，执行 `systemctl --user daemon-reload`。保留地图和所需运行数据，之后才可使用独立开发启动方式。
